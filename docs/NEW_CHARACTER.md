# Creating a new Brawlspace fighter

Every new fighter starts as a copy of **Kung Fu Man 720**, the template that ships in `content/chars/kfm720`.
You then replace its art, sound, stats and moves. Steps 1–3 are design work; from step 4 on it's mostly mechanical.

## 0. What a fighter is made of

| File | Holds | How you make it |
|---|---|---|
| `<id>.def` | Name, author, and which files to load | Generated by the scaffold script |
| `<id>.sff` | Every sprite (frames, portraits) | Built from a folder of PNGs (step 4) |
| `<id>.air` | Animations: frame order, timing, hitboxes | Edit the template's actions |
| `<id>.cns` | Stats and move logic (states) | Edit the template |
| `<id>.cmd` | Button inputs that trigger moves | Edit the template |
| `<id>.snd` | Voices and hit sounds | Keep KFM's at first; replace later |
| `movelist.dat` | Pause-menu move list | Text file |

## 1. Concept sheet (one page)

- **Name, id and look:** for example `blaze`, "Blaze", a street brawler with fire gauntlets.
- **Archetype:** rushdown, zoner, grappler or all-rounder. This decides the stats.
- **Stats compared to KFM:** life 1000, attack 100, walk speed 2.4. Faster fighters should be frailer.
- **Moves:** map each one onto a template move, so the code can be reused:

| Template move (state) | Input | Your move |
|---|---|---|
| Kung Fu Palm (1000–1020) | ↓↘→ + P | e.g. fireball or palm strike |
| Kung Fu Upper (1100–1120) | →↓↘ + P | anti-air |
| Kung Fu Blow (1200–1220) | ↓↙← + P | |
| Kung Fu Zankou (1400–1420) | ↓↘→ + K | dashing attack |
| Kung Fu Knee (1050–1071) | →→ + K | |
| Triple Kung Fu Palm (3000) | ↓↘→↓↘→ + P | super |
| Smash Kung Fu Upper (3050) | ↓↙←↓↙← + P | super |

## 2. Art spec

The template is drawn for a **1280×720** screen (`localcoord = 1280,720`). Match its scale.

- **Size:** a standing frame is about **190×424 px**, and the fighter is about **400 px tall**. Large poses go up to about 500×560 px.
- **Format:** one transparent **PNG** per frame (32-bit RGBA).
- **Anchor (axis):** the point on the ground between the fighter's feet. Keep it in the same spot on every frame, or the fighter will jitter.
- **Direction:** draw everything **facing right**. The engine mirrors the sprites automatically.
- **Consistency:** keep the same proportions, line weight and lighting across frames. That matters more than polish.

### Frames to draw

The template uses 117 animations. You don't need unique art for all of them; reuse frames wherever you can.

**Minimum playable set (about 60–80 frames):**

| Action numbers | Animation | Frames (approx.) |
|---|---|---|
| 0 | Stand (idle loop) | 4–6 |
| 5 / 6 | Turn (standing / crouching) | 1–2 each |
| 10, 11, 12 | Stand→crouch, crouch, crouch→stand | 2, 1–2, 2 |
| 20, 21 | Walk forward, walk back | 6, 6 (can share) |
| 40–47 | Jump start, rise, fall, land | 6–8 total |
| 100, 105 | Run forward, hop back | 6, 3 |
| 120–152 | Guard: stand, crouch, air, plus guard-hit | 3–4 (heavily shared) |
| 200, 210, 230, 240 | Standing light/strong punch and kick | 3–5 each |
| 400, 410, 430, 440 | Crouching light/strong punch and kick | 3–5 each |
| 600, 610, 630, 640 | Air light/strong punch and kick | 2–3 each |
| 800–820 | Throw and thrown | 4–6 |
| 5000–5300 | Getting hit, knockdown, lying down, get-up | 12–15 (shared across many actions) |
| 181, 190–195 | Win pose, intro, taunt | 3–6 each |
| 1000–3051 | Specials and supers | 4–10 each |

**Portraits (required for character select):**

| Sprite | Size | Used for |
|---|---|---|
| `9000,0` | 100×100 | Select-screen icon |
| `9000,1` | 480×560 | Large portrait on the select and versus screens |

### Getting art to Claude

- **Best:** save the PNGs into `content/chars/<id>/art/` (or any folder) and give Claude the path.
- **Artwork from claude.ai:** Claude Code can read **published artifacts** on your account, but not images inside chat conversations. Download those images into a folder first.
- **AI-generated art:** single concept images work well. Animation frames rarely stay consistent from one generation to the next. Generate a concept and portrait, then draw or trace the frames, or use a consistent pose-sheet workflow.

## 3. Name the files for the packer

Name each PNG `<group>_<item>.png`, using the template's sprite numbers.
For example, `0_0.png` … `0_5.png` are the idle frames and `9000_0.png` is the select icon.

An optional `axis.txt` sets anchors as `<group>_<item> <x> <y>`, in pixels from the image's top-left corner.
A `default <x> <y>` line applies to every frame.
Without it, frames anchor at bottom-center and portraits (group 9000) at top-left.

**Start from the template's own frames.** This exports all 281 KFM 720 sprites, with their sprite numbers and anchors,
as reference poses to draw over:

```sh
python3 -I tools/sff_to_png.py content/chars/kfm720/kfm720.sff ~/Desktop/kfm720-frames
```

If you replace frames in place and keep the exported `axis.txt`, the anchors stay correct for every pose.

## 4. Build the fighter

```sh
# 1. scaffold (copies KFM 720, renames, adds to the roster)
python3 -I tools/new_character.py blaze "Blaze" --author "Your Name"

# 2. pack your art into the sprite file (--clsn prints suggested hurtboxes for the .air)
python3 -I tools/png_to_sff.py content/chars/blaze/art content/chars/blaze/blaze.sff --clsn

# 3. rebuild the content bundle and run locally
bash build/wasm.sh --shell-only
python3 web/serve.py 8080      # open http://localhost:8080
```

## 5. Wire up animations and hitboxes (`<id>.air`)

- Each `[Begin Action N]` lists frames as `group,item, x,y, ticks` (60 ticks = 1 second).
  Point them at your sprite numbers and adjust the timing.
- **Clsn2** (blue) boxes are where the fighter can be hit; **Clsn1** (red) boxes are where an attack hits.
  Every attack frame that should connect needs a Clsn1 box.
- In game, open **Practice → Training** and press **Ctrl+C** to show the hitboxes. **Ctrl+D** shows debug info.

## 6. Stats and moves

- **`<id>.cns`:**
  - `[Data]`: life, attack, defence.
  - `[Size]`: height and body width.
  - `[Velocity]`: walk, run and jump speeds.
  - `[Statedef N]` blocks: move logic, where damage, hitstun and knockback are set in each `HitDef`.
- **`<id>.cmd`:** input motions in `[Command]` blocks. The `[Statedef -1]` entries map commands to states.
- **`movelist.dat`:** update the pause-menu list to match.
- For a working example of new moves added on top of KFM (a projectile, a teleport and a new super),
  see Shade in the **DojoClash** repo: `tools/shade_states.cns`.

## 7. Sound (optional at first)

Keep KFM's `.snd` until the art is done. A WAV-to-SND packer can be added later, the same way as the sprite packer.

## 8. Test checklist

- [ ] Appears on character select with its portrait.
- [ ] Idle, walk, crouch and jump show no jitter (the anchor is consistent).
- [ ] Every normal and special hits (Ctrl+C shows red boxes on the active frames).
- [ ] Can be hit in every pose (blue boxes always present).
- [ ] Knockdown and get-up work, and the win pose plays.
- [ ] Specials come out with the listed inputs on both sides of the screen.
- [ ] Plays a full Arcade match against the CPU without errors in the browser console.

## 9. Ship it

Commit and push to `main`. GitHub Actions rebuilds the site, and it's live in about two minutes.

## Sprite tools

| Tool | What it does |
|---|---|
| `tools/png_to_sff.py <art_dir> <out.sff> [--clsn]` | Packs `<group>_<item>.png` frames into an SFFv2 file as 32-bit PNG sprites. Identical frames are stored once. `--clsn` prints a starting Clsn2 box per frame. |
| `tools/sff_to_png.py <in.sff> <out_dir> [--palette N]` | Exports an SFFv2 file to PNGs plus `axis.txt`, ready to repack. Raw, RLE8 and PNG formats are supported; RLE5 and LZ5 sprites are skipped with a warning. |

Both tools need Pillow, which is already installed with this Mac's Python 3.7. `png_to_sff.py` needs it only for `--clsn`.

The pair is tested end to end: exporting KFM 720, repacking him, and playing an Arcade match in the browser shows identical sprites and anchors.

**Colors:** packed sprites are full-color, so palette swaps don't change them. Alternate costumes (palette keys X/Y/Z…)
and the automatic recolor in mirror matches show the same colors. For alternate colors, either draw extra sprite
sets, or tint in the `.cns` with a `PalFX` controller.
